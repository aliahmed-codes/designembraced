# Vercel deployment

This project uses Vercel's Express preset. `src/app.js` exports the Express application, and still starts a local server when run directly.

## Build settings

- Node.js: 24.x
- Install: `npm ci --include=dev`
- Build: `npm run build`
- Static assets: generated by Gulp into `public/`, served by Vercel's CDN
- Pug views: included in the server function through `vercel.json`
- Runtime environment variable: `sanityProjectId` (use the value from your local `.env`)

Local development: `npm run dev`. Local production-style run: `npm run build`, then `npm start`.

## Deploy from this computer

The project is linked to `atlantiqs/designembraced`. Local linking metadata is in ignored `.vercel/`.

```powershell
npx vercel deploy
npx vercel deploy --prod
```

The first command normally creates a preview; the second updates production. The initial deployment of a new project can become production automatically.

`sanityProjectId` is configured in Vercel for Preview and Production. Environment files and local review downloads are excluded from uploads by `.vercelignore`.

Automatic Git deployment is not connected: Vercel reported that the logged-in account lacks admin/write access to `aliahmed-codes/designembraced`. Connect that repository under the Vercel project's Git settings using an account with access if automatic deployment on push is desired.

Official framework documentation: https://vercel.com/docs/frameworks/backend/express
